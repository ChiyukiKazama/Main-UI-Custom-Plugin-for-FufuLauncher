# 主界面 UI 自定义（MainUICustomizer）

可分别隐藏主界面元素、缩放 HUD 单元、调整四边边距及右上按钮对齐。默认不隐藏元素，缩放为 1，边距为 0。

## 安装与配置

将发布包中的 MainUICustomizer.dll 和 config.ini 放入启动器插件子目录。升级时保留自己的 config.ini，只替换 DLL，完整重启游戏后生效。插件只读取配置，不改写用户设置。

同一个 DLL 支持国服与国际服 7.2。插件根据宿主文件名选择原生入口表，并校验 PE 指纹和该表的 43 个入口字节。默认配置的 GameVersion 为 7.2，旧配置升级到 7.2 时需手动同步这一项。

设置可在启动器配置页或 DLL 同目录的 UTF-8 config.ini 中修改。保存触发文件变更通知；相同选项值不会重复应用，空文件或无效配置保留上一份有效设置。

## 功能

共 25 个显隐开关。

| 设置 | 范围 |
| --- | --- |
| 隐藏主界面所有 UI | 覆盖以下已识别 HUD 元素，保留输入、UID、敌人与 Boss 血条等区域 |
| 左上角按钮组 | 派蒙、联机、元素视野、任务入口、教程入口、至冬手册及周围地区/场景按钮，保留小地图和任务追踪 |
| 右上角按钮组 | 活动、背包、角色、祈愿、纪行、手册及千星奇域入口 |
| 独立区域 | 小地图、队伍栏、任务追踪、聊天按钮、聊天面板、技能及操作区域、底部血量与角色状态、交互提示、网络延迟 |
| 独立入口 | 派蒙、活动、背包、角色、祈愿、纪行、手册、联机、千星奇域、元素视野、任务、教程、至冬手册 |

已有配置可从发布包的 `config.ini` 复制 `[HideTutorialEntry]` 整节。将 `Value` 设为 `1` 可隐藏教程按钮、红点和教程提示。左上角按钮组和全局隐藏仍会覆盖此项。

父级开关覆盖子项，但各子项自己的配置保持可编辑。隐藏使用明确 HUD 区域内绘制组件的透明度与绘制状态，保留节点、输入和原有点击区域。按钮的已识别通知红点也在对应范围内。所有已识别 HUD 区域统一处理附属绘制：队伍、小地图追踪标记、技能及其他区域内的粒子、网格、拖尾、线条等 Renderer 组件随所属区域隐藏或恢复，不设独立特效选项，不要求 MonoUIEffect 或固定节点名。同节点的文字、图像和多个绘制组件分别缓存，世界绘制器不在处理范围内。

## 缩放、边距与对齐

| 配置键 | 说明 |
| --- | --- |
| Scale | 0.25～2.5，默认 1，完整 HUD 单元以原生定位点等比缩放 |
| MarginLeft / MarginRight | 左右边距独立，范围 -4000～4000，默认 0 |
| MarginTop / MarginBottom | 上下边距独立，范围 -4000～4000，默认 0 |
| AlignRightButtons | 隐藏部分右上按钮后，将其余按钮按原顺序移到最靠右的原生可用位置，保留纵向位置 |

边距以画布坐标计，正数向内，负数向外。左边距作用于小地图及周围按钮、任务提示、聊天；右边距作用于右上按钮、网络延迟、队伍与技能区域；上边距只作用于顶部按钮、小地图与网络延迟；下边距作用于聊天、技能区域与底部角色状态。队伍栏只响应右边距。

主界面根节点不参与缩放或边距修改。缩放以完整 HUD 单元为对象：小地图、单个按钮、每行队伍信息、每组技能及按键提示、各底部状态区域分别保持原生定位点；聊天入口和展开面板作为同一单元，显隐开关仍然独立。单元内部的图标、文字、底图、遮罩、特效及点击区域同步缩放，保留原生相对布局。空占位节点和尺寸较大的布局容器不会额外引入中心补偿位移。

四边边距在区域外层单独叠加，整体平移小地图及左上区域、右上按钮组、技能区域、聊天区域和底部各状态区域；队伍栏按完整行平移。倍率不会重复作用于子节点，边距也不会随倍率放大或缩小。

缩放和边距均由缓存的布局单元统一处理。布局应用或恢复后，会刷新受影响的平滑遮罩和矩形遮罩裁剪范围，避免血条、地图或技能图标被旧范围截断。

## 热重载与对象缓存

缓存随主界面实例保留：第一次请求某个区域时建立该区域的对象缓存。之后调整显隐、倍率或边距时比较配置差异，只更新受影响的对象。关闭选项会恢复属性并保留缓存，再次开启直接复用。绘制显隐和单元布局分别缓存；右对齐只处理右上按钮。

配置热重载不会重新遍历全部已缓存区域。新增区域、主界面实例替换、绘制组件启用、特效或预制体创建、交互行或键位实例创建/挂载及用户明确刷新时查找对象。生命周期通知合并后只补充受影响的已识别分支。启用缩放、边距或对齐时，绘制回调检查缓存单元的位置和缩放，组合原生动画与自定义变换，并刷新受影响遮罩；默认布局不读取这些属性。启用隐藏时，同一回调在游戏更新绘制后维护已缓存对象的透明度与绘制状态，处理页面返回、冷却文字刷新和特效重新启用；属性未变化时不重复写入。没有定时 UI 扫描、每帧 UI 树遍历或全局属性读写挂钩。

## 快捷键与自定义路径

| 配置项 | 默认键 | 功能 |
| --- | --- | --- |
| ToggleKey | Home | 临时恢复原始界面，再按恢复自定义；保留对象缓存 |
| DumpKey | End | 明确刷新一次缓存，并导出插件目录的 ui-tree.txt |

按住不重复触发，仅游戏在前台时响应。键值为 Windows 虚拟键码，填入 0 可禁用；缺少配置时不启用快捷键。

将主页面内导出的路径填入 HiddenPaths，多条用 | 分隔。支持完整路径或相对 /Canvas/Pages/InLevelMainPage 的路径，最多 128 条，不支持通配符或 ..。自定义路径仍受已识别 HUD 区域和绘制类型限制，不会关闭任意父容器。外部任务提示由“隐藏任务追踪与指引”控制，其他页面的导出路径用于排查。

```ini
[HiddenPaths]
Type = string
Value = GrpMainPage/MapInfo/BtnClock | GrpMainPage/NetworkLatency
```

插件不生成运行日志。ui-tree.txt 仅在用户按下导出快捷键时生成，覆盖 /Canvas 下的 UI 页面与额外挂载的提示，记录节点名、绝对路径和启用状态，并附带任务提示组件类型及已识别 HUD 的实际坐标与插件布局坐标，便于排查错位；不读取聊天正文或 UID 内容。

主界面创建、配置变更、对象生命周期通知和快捷键操作会更新缓存；缓存单元的缩放和边距会随游戏动画保持。任务追踪与交互提示按专用组件确认范围，支持 UI 画布内额外挂载的提示；MonoQuestTrace 的标题、图标、距离及指引、独立目标距离文字和返回任务按钮也纳入任务隐藏。任务组件与其他 HUD 共用区域登记、对象缓存、显隐及恢复流程。游戏原有的 MonoQuestTrace.Tick 调用只登记尚未进入区域表的具体实例，选项关闭时也保留该来源，之后开关直接复用缓存；不遍历整个 UI 画布，不为每个绘制组件逐层查找任务类型。已有绘制组件重新启用时验证缓存身份和父链，新绘制组件只补充自身，预制体、特效或交互行的明确创建事件才检查对应小分支。额外挂载的提示只处理绘制显隐。End 可手动刷新并导出 UI 画布树，未识别的绘制类型暂不处理。当前使用 WillRender、主界面 Awake 和十个对象生命周期/实例登记事件挂钩。交互键位图像与文字在当前键位或切换键位图标刷新后补充缓存；同名克隆按对象身份分别处理。

## 构建与打包

需要 Visual Studio C++ v145、Windows SDK 和 PowerShell 7。

```powershell
.\build.ps1
.\package.ps1
```

默认 Release/x64，可用 -Configuration Debug 构建调试版本。DLL 在 bin/x64/Release，中间文件在 obj。构建仅在输出目录缺少配置时复制根目录默认配置；-SyncDefaultConfig 可明确覆盖输出默认配置。

打包读取根目录 config.ini，核对版本并验证 ZIP 条目内容哈希，拒绝覆盖已有同名包。发布包顶层只含 DLL 和配置；可通过 package.ps1 -OutputDirectory 指定输出目录。版本来自 src/Version.h。

## GitHub Actions

默认分支推送及 PR 会执行 Release x64 构建、UPX 压缩与成品校验，使用 `src/Version.h` 的基础版本。其他分支推送不构建，不通过 tag 推送发布。流程使用带 VS 2026 的 `windows-2025-vs2026` runner，经 `vswhere` 查找 VS 18.x MSBuild，明确使用 v145。

发布时，在 **Actions → Build and manual release → Run workflow** 选择默认分支，填写 `version`（例如 `1.2.3`）。版本必须为三段非负整数，不带前导零、前缀、空白或后缀；受 Windows VERSIONINFO 限制，每段不超过 65535。不自动递增，也不提交或回写源码。

手动版本写入临时版本资源和包内默认 INI 的 `General.Version`，用于 DLL 产品版本、ZIP 文件名、Release 标题及 `v版本号` tag。DLL 文件版本采用对应的四段 Windows 格式，例如 `1.2.3.0`。打包始终读取仓库根目录默认配置，仅在包内替换版本行，不读取本机输出目录中的配置，也不操作用户已安装的配置。

CI 从[官方 UPX 5.0.2 Release](https://github.com/upx/upx/releases/tag/v5.0.2) 下载固定的 win64 ZIP，并核对 `policy.json` 固定的 SHA256，再执行 `--best --ultra-brute`。必须通过 UPX 完整性、解压、体积减小、x64 PE DLL、版本资源、文件名与 ZIP 根目录校验。解压后的 DLL 不要求与原 DLL 哈希相同。

加载检查使用独立的非游戏 x64 PowerShell 子进程。`policy.json` 的源码审查指纹固定已审查的游戏宿主保护、全局初始化及构建输入；指纹变化时会停止加载检查。以后修改这些输入时，须先审查 `PluginWorker` 的非游戏提前返回及全局初始化安全性，再人工更新 `safeLoadSourcesSHA256`。版本资源与 CI 脚本不参与该运行时代码指纹。

发布在全部构建校验通过后单独执行：已有同版本公开 Release 则跳过；存在同版本草稿则停止。没有同版本 Release 时，允许复用删除 Release 后遗留的 tag，将其更新为本次构建提交。新发布先创建草稿，再核对发布状态并创建或更新 tag，仅上传 ZIP，核对附件状态、名称、大小和下载回读 SHA256 后公开。失败保留草稿供人工检查，后续运行不会接管该草稿或覆盖附件；并发变化会停止发布。

构建权限为 `contents: read`，发布作业仅在默认分支手动触发时获取 `contents: write`，使用仓库自带的 `GITHUB_TOKEN`，无需 PAT。发布作业按仓库串行执行，不取消正在执行的发布。ZIP、`.sha256` 和 `compression-report.json` 作为 Actions artifacts 保留 14 天；Release 只附带 ZIP。所用官方 Actions 固定到提交 SHA。

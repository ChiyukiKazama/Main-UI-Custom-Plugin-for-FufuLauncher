# 主界面 UI 自定义（MainUICustomizer）

**1.0.0** · 可分别隐藏主界面元素、围绕元素中心缩放、调整四边边距和自定义隐藏路径。

## 安装与升级

首次安装时，将 `MainUICustomizer-1.0.0.zip` 中的 `MainUICustomizer.dll` 和 `config.ini` 解压到启动器的插件子目录，在插件管理中启用后启动游戏。DLL 自带静态运行库，无需额外安装运行时。

升级时保留自己的 `config.ini`，只替换 DLL。更换 DLL 后需重新启动游戏；运行中不支持热卸载。整体启停由启动器的插件开关控制。

## 显隐设置

默认保留游戏原始界面，所有隐藏项关闭。隐藏通过透明度和绘制状态实现，保留节点、输入组件、可交互状态及原点击区域。取消隐藏会恢复游戏最后请求的状态，不会强制显示原本未解锁或由游戏隐藏的入口。

| 设置 | 范围 |
| --- | --- |
| 隐藏主界面所有 UI | 覆盖全部主界面隐藏项 |
| 隐藏左上角按钮组 | 派蒙、联机、元素视野、任务入口、至冬手册及周围地区/场景按钮；保留小地图和任务追踪文字 |
| 隐藏右上角按钮组 | 活动、背包、角色、祈愿、纪行、冒险之证等手册及千星奇域入口 |
| 独立元素 | 小地图、队伍栏、任务追踪与指引、聊天按钮、聊天消息面板、技能及操作区域、底部血量与角色状态、交互提示、网络延迟 |
| 独立入口 | 派蒙、联机、元素视野、任务、至冬手册、活动、背包、角色、祈愿、纪行、手册、千星奇域 |

共 24 个显隐开关。总开关的覆盖关系仅在插件内部处理；配置页始终显示并保存各子项自己的选择，子项保持可编辑。

聊天按钮控制左下角图标与 Enter 提示，聊天面板控制上方的消息内容和背景，两者独立。底部血量与状态包括角色血量、等级、附近的元素/增益及相关状态条，保留敌人和 Boss 血条。任务追踪同时处理主界面内提示和捕获到的外部持续追踪节点。UID 由主插件控制。

左右按钮组对应配置键 `HideTopButtons`（左上角）和 `HideMainButtons`（右上角）。

## 缩放、边距与对齐

| 配置键 | 说明 |
| --- | --- |
| `Scale` | 0.25～2.5，默认 1。各 HUD 单元围绕自身矩形中心缩放，保留中心位置，嵌套单元只缩放一次 |
| `MarginLeft` / `MarginRight` | 左、右边距分别设置，范围 -4000～4000，默认 0 |
| `MarginTop` / `MarginBottom` | 上、下边距分别设置，范围 -4000～4000，默认 0 |
| `AlignRightButtons` | 默认关闭。隐藏部分右上角按钮后，其余按钮按原顺序移到最靠右的原生可用位置 |

边距单位为画布坐标。正数从原始边界向内留白，负数向外扩展，0 保留原边距。元素缩放与四边边距分别计算；边距导致可用宽高不足 1 时，保留原始区域。

自动右对齐保留纵向位置，可与元素缩放同时使用，不会打开游戏自身隐藏的按钮。关闭对齐、临时恢复或页面替换时，还原游戏原生布局。

## 快捷键与自定义路径

| 配置键 | 默认键 | 功能 |
| --- | --- | --- |
| `ToggleKey` | Home | 临时恢复原始显隐与布局，再按恢复自定义 |
| `DumpKey` | End | 进入世界后导出插件目录中的 `ui-tree.txt` |

两项均为单键触发，每次按下执行一次，按住不重复执行，仅游戏窗口在前台时响应。`Value = 0` 或缺少该项时禁用对应快捷键。键值使用 Windows 虚拟键码。

将导出文件中的节点路径填入 `HiddenPaths`，多条用 `|` 分隔，清空后恢复。支持完整路径或相对 `/Canvas/Pages/InLevelMainPage/` 的路径，按大小写精确匹配，最多 128 条，不支持通配符、空路径段和 `..`。只接受主界面根及其子节点；外部任务追踪使用 `HideQuestTrack` 控制。

```ini
[HiddenPaths]
Type = string
Value = GrpMainPage/MapInfo/BtnClock | GrpMainPage/NetworkLatency
```

导出包括自身未启用的子节点，以及已捕获的外部任务追踪节点；只记录节点名、路径和自身启用状态，不含消息正文或 UID 数字。导出上限为 20000 个节点、64 层。

## 配置保存

可在启动器配置页或 DLL 同目录的 UTF-8 `config.ini` 中修改设置。插件只读取配置，通过目录变更通知加载，在游戏 UI 渲染事件中应用；无效或不完整的文件会保留上一份有效设置。没有定时目录扫描或逐帧整树扫描。运行时不生成日志文件，`ui-tree.txt` 仅在按下导出快捷键时生成。

项目根目录的 `config.ini` 是发布默认配置，键位和显示文字均以此文件为准。构建、打包和运行时均不改写它。构建只在输出目录缺少配置时复制默认配置；若要明确覆盖输出配置，使用 `build.ps1 -SyncDefaultConfig`。打包直接读取根目录配置，保留原始字节，不使用输出目录中的本机配置。

## 构建与打包

需要 Visual Studio C++ v145、Windows SDK 和 PowerShell 7。

```powershell
.\build.ps1
.\package.ps1
```

默认构建 Release/x64，也可使用 `build.ps1 -Configuration Debug`。DLL 位于 `bin/x64/Release/`，中间文件位于 `obj/`，发布包位于 `dist/`。构建所需文件为 `src/`、`vendor/minhook/`、`MainUICustomizer.vcxproj`、`build.ps1` 与根目录配置。

源码版本由 `src/Version.h` 定义，DLL 文件版本和产品版本使用该定义。打包会核对 DLL 产品版本与根目录配置的 `General.Version`，验证 ZIP 中两个文件的 SHA-256，并拒绝覆盖已有同名发布包。正式 ZIP 顶层仅包含 DLL 和配置。

测试目录、辅助检查脚本、构建输出及发布产物已加入 Git 忽略，保留在本地供维护检查使用。

## GitHub Actions

默认分支推送及 PR 会执行 Release x64 构建、UPX 压缩与成品校验，使用 `src/Version.h` 的基础版本。其他分支推送不构建，不通过 tag 推送发布。流程使用带 VS 2026 的 `windows-2025-vs2026` runner，经 `vswhere` 查找 VS 18.x MSBuild，明确使用 v145。

发布时，在 **Actions → Build and manual release → Run workflow** 选择默认分支，填写 `version`（例如 `1.2.3`）。版本必须为三段非负整数，不带前导零、前缀、空白或后缀；受 Windows VERSIONINFO 限制，每段不超过 65535。不自动递增，也不提交或回写源码。

手动版本写入临时版本资源和包内默认 INI 的 `General.Version`，用于 DLL 产品版本、ZIP 文件名、Release 标题及 `v版本号` tag。DLL 文件版本采用对应的四段 Windows 格式，例如 `1.2.3.0`。打包始终读取仓库根目录默认配置，仅在包内替换版本行，不读取本机输出目录中的配置，也不操作用户已安装的配置。

CI 从[官方 UPX 5.0.2 Release](https://github.com/upx/upx/releases/tag/v5.0.2) 下载固定的 win64 ZIP，并核对 `policy.json` 固定的 SHA256，再执行 `--best --ultra-brute`。必须通过 UPX 完整性、解压、体积减小、x64 PE DLL、版本资源、文件名与 ZIP 根目录校验。解压后的 DLL 不要求与原 DLL 哈希相同。

加载检查使用独立的非游戏 x64 PowerShell 子进程。`policy.json` 的源码审查指纹固定已审查的游戏宿主保护、全局初始化及构建输入；指纹变化时会停止加载检查。以后修改这些输入时，须先审查 `PluginWorker` 的非游戏提前返回及全局初始化安全性，再人工更新 `safeLoadSourcesSHA256`。版本资源与 CI 脚本不参与该运行时代码指纹。

发布在全部构建校验通过后单独执行：已有同版本公开 Release 则跳过；存在同版本草稿则停止；已有 tag 指向其他提交则停止。新发布先创建草稿，将 tag 固定到本次构建提交，仅上传 ZIP，核对附件状态、名称、大小和下载回读 SHA256 后公开。失败保留草稿供人工检查，后续运行不会接管该草稿、覆盖附件或移动 tag。

构建权限为 `contents: read`，发布作业仅在默认分支手动触发时获取 `contents: write`，使用仓库自带的 `GITHUB_TOKEN`，无需 PAT。发布作业按仓库串行执行，不取消正在执行的发布。ZIP、`.sha256` 和 `compression-report.json` 作为 Actions artifacts 保留 14 天；Release 只附带 ZIP。所用官方 Actions 固定到提交 SHA。

## 验证与支持范围

Release/x64 构建已通过，发布包中的 DLL 与配置按 SHA-256 核对。本地保留的离线回归覆盖显隐预设的输入状态、恢复、自定义路径、聊天分离、动态节点、中心缩放、四边边距和自动右对齐。

离线输入检查验证节点启用状态与组件属性，不代表真实键盘/鼠标回调已经完成实机验收。不同分辨率、手柄/触屏布局、动画、传送和与其他插件并用仍需游戏内验证。仅对匹配版本头和函数入口的国服 7.1 映像启用，其他版本停止初始化。
